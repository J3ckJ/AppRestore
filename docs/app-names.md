# app_names — имена для плиток недостающих приложений

Модуль: `app_names.py` (stdlib + `region_probe` + встроенный список `delisted_search`, без ipatool). Тесты: `test_app_names.py` (68, без сети).
Правовая рамка: `LEGAL.md` §1.10, та же, что у `region_probe`.

## Зачем
У плитки `missing` (приложения нет на iPhone) имени часто нет: installation_proxy его не знает,
а кэш покупок до входа пуст. Публичный lookup отдаёт `trackName` анонимно, до входа и после.

## Как работает
`GET https://itunes.apple.com/lookup?id=a,b,c&country=xx` или `?bundleId=a,b,c&country=xx`.
- Пачки по 100 (`BATCH_SIZE`). Живой тест 10.10.2026: на 150 `resultCount` совпадал, на 200 ответ обрезался.
- Ответ не держит порядок и молча выкидывает ненайденные. Поэтому сопоставление идёт по полю
  (`trackId` для `id=`, `bundleId` для `bundleId=`, без учёта регистра), а не по индексу.
- id и bundleId уходят разными запросами, в одном URL их не смешиваем.
- **Ключ выхода — ровно входной токен строкой**: `284882215` → `"284882215"`, `"com.A.b"` → `"com.A.b"`.
  Так остаётся при разбивке на пачки и при переходе к следующей стране. Если один id передан
  разными токенами (`1`, `" 1 "`), запрос будет один, а заполнятся все ключи.
- Не найденное ни в одной витрине в словарь не попадает. Пустой `trackName` за имя не считается.

## Запасное имя: встроенный список delisted_search
После цепочки витрин всё, что осталось без имени (обычно это приложения, удалённые из всех витрин),
дозаполняется по `track_id` (для `ids`) и по `bundleId` без учёта регистра (для `bundle_ids`) из
`delisted_search.builtin_entries()`. По умолчанию (`BUILTIN_STRICT=True`, LEGAL.md §1.13) это только уровень A, сейчас 6 записей.
Уровень B в запасные имена не попадает.
- Это просто чтение константы. Wayback-путь `delisted_search` (`search`/`search_delisted`/`_default_fetcher`) не вызывается,
  так что в web.archive.org запрос не уходит никогда. Это проверяет тест `test_builtin_fallback_never_requests_archive`
  (архив и opener запрещены, имена всё равно приходят, вызовов ноль).
- Имя от Apple не перезаписывается. Запасное имя ставится только в ключи, которые ещё пусты.
  Ключ — тот же входной токен.
- Работает, даже если lookup упал во всех витринах. Отключается через `AppNames(..., builtin_fallback=False)`.
- `delisted_search.py` не менялся: используется его публичный `builtin_entries()`.

## Цепочка витрин
| Состояние | Порядок |
|---|---|
| Вошли (`account_country` задан) | витрина аккаунта → регион iPhone → `US` |
| Не вошли | регион iPhone → `US` |

Следующая витрина спрашивается только для ещё не найденных. Дубли схлопываются (US-аккаунт + `en_US` = один запрос).
Ошибка сети в витрине: не кэшируется, ключи переходят к следующей. Не больше 3 витрин, перебора нет.

**Регион iPhone** — это РЕГИОН из `Locale` (`com.apple.international`), то есть часть после `_`, а не язык:
`ru_RU` → `ru`, `en_RU` → `ru` (язык английский, но витрина RU), `zh-Hans_CN` → `cn`, `en_US@calendar=…` → `us`.
Голый язык (`en`) или нестрановой регион (`en_001`) означают, что региона нет, и сразу идёт `US`.
Витрина аккаунта: ISO2 в любом регистре (`RU` → `ru`). Storefront-id вида `143441-1,34` пропускается.
Язык `trackName` задаёт витрина (`country=ru` → русские имена). Отдельный `lang=` не шлём.

Явные варианты: `countries=["ru","us"]` (1–3 ISO2, US сам НЕ добавляется, мусор → `ValueError`),
`country="RU"` (ровно одна витрина). Смешивать с `account_country`/`device_locale` нельзя → `ValueError`.

## Что берётся из region_probe (без копий)
`AppNames` строится поверх `RegionProbe` (по умолчанию `region_probe.default_probe()`), `region_probe.py` не менялся:
- сеть: `probe._fetch` = `region_probe._default_fetcher` (opener без cookie/auth-хендлеров) и `region_probe.HEADERS` (2 заголовка);
- ограничение частоты: `probe._throttle()` под `probe._lock`. Лимитер **общий** с `region_probe`,
  ≤1 запрос/с на процесс для обоих модулей;
- часы и TTL: `probe._clock`, `POSITIVE_TTL_S` (24 ч) / `NEGATIVE_TTL_S` (6 ч);
- кэш: имена лежат в своём словаре (`(вид, ключ, витрина)`, тот же TTL). Каждый id-запрос ещё и
  пишет «есть/нет + цена» в кэш `region_probe` (`probe._store`), так что потом `classify()` для тех же id
  и витрин в сеть не ходит;
- `LookupError_`, `_norm_track_id`, `_norm_price`, `LOOKUP_URL`, `MAX_IDS_PER_CALL` (2000).

## Соответствие §1.10
| Условие | Как соблюдено |
|---|---|
| 1. Анонимно | Opener и заголовки из region_probe. В URL только `id`/`bundleId` и `country`. Модуль не импортирует `ipatool_api`/`license_guard` и сам opener не строит. Всё это проверяют тесты. |
| 2. Только список пользователя | Ключи приходят снаружи (недостающие приложения пользователя), не больше 2000 за вызов, поиска нет. |
| 3. Фиксированные витрины, частота | Не больше 3 витрин (аккаунт, регион iPhone, US); общий лимитер ≤1/с; пачки по 100; кэш с TTL. |
| 4. Только текст | На выходе только имена (из lookup или встроенного списка уровня A, без сети). Ничего не покупает и не скачивает, действий не предлагает. |

Логи: только счётчики (ключи / найдено / запросы / ошибки).

## Оговорки
- Удалённое отовсюду приложение lookup не найдёт ни в одной витрине. Имя будет только у тех, что есть во встроенном
  списке уровня A. Для остальных — запасная цепочка Димы (`iTunesMetadata`, покупки после входа, «Приложение»).
- Встроенное имя записано как в App Store на момент проверки (без локализации под витрину).
- Блокирующий вызов: до 3 × ⌈N/100⌉ запросов по ≥1 с каждый.
