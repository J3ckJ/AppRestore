# AppRestore: ускорение и интерфейс — 13 ноября 2026

Оптимизация 0.4.1 с сохранением прежних исправлений. Ниже — что изменилось
и как воспроизвести замеры.

## Изменения

- Общий пятисекундный снимок приложений для GUI: три представления используют
  одно USB-чтение. Обновление и установка сбрасывают снимок. Подтверждение
  установки всегда обращается к телефону напрямую; CLI по умолчанию читает заново.
- Параллельные представления используют один проход по библиотеке IPA.
- Большие списки не формируются повторно при каждом событии прогресса. Поиск,
  выбор, сортировка, изменение данных и доступности корректно обновляют строки.
  Закреплённый заголовок находится без копирования и обхода всего списка.
- До четырёх фоновых загрузок иконок; запись метаданных и изображений атомарная.
  Готовые скруглённые иконки используются без повторного декодирования оригинала.
- Сначала видны покупки из кэша, затем результаты App Store, затем доступность.
  Устаревшие запросы не запускают оставшиеся сетевые этапы. Уже отправленный
  запрос может завершиться, но его результат не подменяет новый поиск.
- Цены запрашиваются пакетно. Некорректная цена не превращается в бесплатную.
- Кнопки очистки, рамка фокуса, Enter для немедленного поиска, индикаторы поиска
  и проверки. Выделение текущей установки, перенос длинных названий групп,
  сокращение длинных названий в очереди без перекрытия статуса.

## Воспроизводимые замеры

Один Mac, Python 3.13.0, Qt 6.9.3. Искусственные данные, без аккаунта Apple,
реального устройства и сети: 5000 строк, последовательный USB-транспорт с
задержкой 40 мс на чтение, 24 независимые иконки с задержкой 25 мс.
Время списка — медиана семи запусков; заголовка — трёх. Остальные сценарии —
один запуск. Замеры выполнены последовательно после завершения сборки.

| Сценарий | До, мс | После, мс | Отношение |
|---|---:|---:|---:|
| Повторная подготовка 5000 строк | 74.52 | 2.06 | 36.1× |
| Новый запрос по 5000 строкам | 74.65 | 41.32 | 1.8× |
| 2000 чтений закреплённого заголовка | 207.65 | 2.06 | 101.0× |
| Три представления телефона, имитация USB | 136.17 | 53.26 | 2.6× |
| 24 иконки, имитация задержки сети | 680.18 | 174.99 | 3.9× |

Число USB-чтений в сценарии трёх представлений: **3 → 1**.
Повторное формирование списка выигрывает за счёт переиспользования строк;
первый новый запрос ускоряется меньше, что показано отдельно. Эти результаты
не означают такого же ускорения всего приложения или загрузки IPA с Apple.
Время сети, входа с 2FA и установки iOS зависит от внешних систем.

В исходниках: `scripts/performance_benchmark.py`. Пример запуска из корня:

```sh
python scripts/performance_benchmark.py --source . --output results.json
```

Для сравнения используйте этот же скрипт с `--source /путь/к/старым/исходникам`.
Нужны PySide6 и обычные зависимости проекта.

## Проверка

- Полный набор: **1367 passed, 22 skipped, 67 subtests passed**. Одно предупреждение
  о будущей совместимости стороннего pytest-плагина anyio.
- После последних правок QML: **59 passed**.
- Отдельные проверки: совместное чтение USB, истечение срока кэша, его сброс при
  установке, поздний результат старого чтения, повтор после ошибки, свежесть CLI,
  обновление выбора/фильтров, пакетные цены и прекращение устаревшего поиска.
- 29 экранов отрендерены на демонстрационных данных; проверены поиск, список,
  установка и узкие подписи. В примерах используются нейтральные иконки-заглушки.
- Нативная сборка Mac Intel создана PyInstaller, подписана локальной ad-hoc
  подписью; `codesign --verify --deep --strict`, встроенный `--self-test` и
  `--update-health-check` распакованной сборки прошли.
- Windows и Apple Silicon здесь не собирались. Проверки на физическом iPhone
  для этой оптимизированной сборки не выполнялись.
