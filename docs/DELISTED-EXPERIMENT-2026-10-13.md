Среда: Linux amd64, Python 3.12.14, Go 1.25.0; ipatool `cde7d00`
с патчами AppRestore 0001–0007. Использован предоставленный для проверки
запасной аккаунт. Страна прочитана из его сессии, storefront не подменялся.

**Доступ к 33 приложениям из «Найти» на этом аккаунте не получен.**
Это результат конкретной проверки, а не доказательство удаления файлов Apple
или невозможности восстановления на другом аккаунте. Новая лицензия обычного

Обезличенные ответы по каждому ID: [JSON отчёт](diagnostics/ru-delisted-2026-10-13.json).
Отчёт не содержит Apple ID, DSID, cookies, токенов, GUID, URL пакетов или SINF.
IPA и материалы входа в репозиторий не включаются.

Новая подтверждённая лицензия Firefox добавлена на тестовый аккаунт в ходе
этой проверки. Неоднозначный ответ для «Апгрейда» консервативно занял один слот
`purchase_uncertain`; повторной покупки для него не было. Явные отказы Apple
не засчитывались как полученные лицензии. Общие ограничения 5/сутки и 15/всего,
проверка цены и обязательный шлюз лицензий оставались включены.

У контролей старый volumeStore возвращает пустой HTTP 200, а redownload —
HTTP 500. При этом закреплённые `updateProduct` и `ent/download` работают.
Следовательно, один неудачный канал загрузки не характеризует весь аккаунт.
Для снятых банков каталог не дал external version ID: закреплённые каналы
для них не проверены, номера сборок не подбирались. В отчёте это прямо указано
как `version_unavailable`, а не как отказ проверенного канала.

Установка на iPhone не проверялась: устройство к этой среде не подключено.
Предложение пакета, фактическая загрузка и работоспособность установленного
банковского приложения — три разных результата.

## Что исправлено

1. Продуктовые POST-запросы теперь сохраняют тело и метод при 301/302/307/308.
   Редирект допускается только на сервер Apple, с тем же путём операции и
   параметрами, максимум три перехода. Диагностика и штатная загрузка используют
   один обработчик. Это подтверждено тестами; живые отказы банков не объясняются
   этим исправлением и после него сохранились.
2. HTTP 500 больше не означает «лицензия уже есть». Неоднозначные ответы
   отмечаются как `purchase_unconfirmed`, учитываются в журнале и не вызывают
   автоматического повтора покупки. Успех требует HTTP 200, `purchaseSuccess`
   и явно присутствующего нулевого `status` в ответе.
3. Для каждого уже разрешённого запроса лицензии сохраняется безопасный след:
   `STDQ`/`GAME`, HTTP-код, числовой `failureType`, исход. Можно отличить новую
   лицензию от старой, отказа и потерянного ответа.
4. Добавлен запуск эксперимента без окна. По умолчанию он только читает
   метаданные. С `--acquire-license` использует штатный шлюз; после неопределённого
   ответа проверяет доступ ещё один раз без повторной покупки.

## Как повторить

Сначала собрать патченый ipatool и войти через обычный интерфейс AppRestore.
Пароль Apple ID и код 2FA в аргументы и переменные окружения не передаются.

```bash
bash packaging/bootstrap-ipatool.sh
.venv/bin/python -m apprestore_core.restore_diagnostics \
  --country RU --app 1117817509 --app 1406492297 \
  --app 610003290:838594835 --output build/diagnostics/readonly.json
```

Команда попросит пароль локальной связки, а не Apple ID. До восьми конкретных
приложений за запуск; страна должна совпадать с настоящей страной аккаунта.
Для отдельного разрешённого запроса новых лицензий добавить `--acquire-license`
и выбрать другой файл отчёта. Не использовать повторные запуски для обхода
отказов или лимитов. `state: complete` означает завершение эксперимента,
а фактический результат каждого приложения находится в `results[].outcome`.

## Вывод для дальнейшей реализации

Исчезновение карточки не запрещает собственную повторную загрузку: нужны
лицензия аккаунта и канал, на котором Apple выдаёт пакет. Известный ID версии
позволяет проверить дополнительные каналы даже без карточки. Существующие
`STDQ → GAME` и канал Asspp/ApplePackage проверены на уровне исходников:
в закреплённом ipatool тот же `MZFinance.woa/wa/buyProduct`, те же параметры
покупки и фиксированная цена 0. Повторить те же запросы ещё раз — не новый путь.

Успех Infinity Blade III, описанный пользователем, пока не воспроизведён на
этом RU-аккаунте. Следующая содержательная проверка — исходный успешный аккаунт
и точная версия старой CLI, с историей до запроса, ответом покупки и выдачей
SINF после него. Отдельная проверка для банков требует аккаунта с собственной
старой лицензией и/или точного external version ID из своей сохранённой IPA.
Эти данные помогут различить выдачу новой лицензии, повторную загрузку и
неверную старую трактовку HTTP 500. Сейчас нельзя честно обещать получение
новой лицензии на любой удалённый банк.
