# ipatool: восстановление снятых приложений и аудит интеграции

Проверено 12.10.2026 по исходникам `majd/ipatool` на закреплённом коммите
`cde7d00355e152714377b953ec57438626d3cb5a` и коду AppRestore. Проверка
сборки/моков не доказывает доступность конкретного приложения для Apple ID.

## Где была потеря рабочего пути

Публичный lookup отвечает про карточку магазина, а не про лицензию и пакет.
Отсутствие карточки не является окончательным отказом в повторной загрузке.
Пример пользователя с Infinity Blade III согласуется с этим разделением;
повторно на его аккаунте в ходе этой проверки игра не скачивалась.

У форка уже есть цепочка `ent/download` (KBSync/SAP), `volumeStoreDownloadProduct`,
`redownload`, затем для закреплённой версии `updateProduct`. Однако запасной
`redownload` для iOS запрашивал актуальную версию из публичного каталога и
останавливался на `platform version lookup returned no app/no offers`.

Патч 0004 также направляет ответ `2059` («временно недоступно») обычного
канала в повторную загрузку того же аккаунта. Это ещё не отсутствие лицензии.
Ошибки лицензии `9610`, входа, несовпадения магазина и прочие отказы не
переопределяются как недоступность; покупка через запасной канал не проводится.

При отсутствии карточки/offer разрешается один запрос `redownload` без номера
версии: пакет выбирает Apple для собственной сессии пользователя. Если ответ
успешен, проверяются числовой ID, bundle ID и единственность результата.
Затем ipatool проверяет `iPhoneOS` в IPA и добавляет выданные Apple SINF.
AppRestore дополнительно проверяет IPA, ожидаемый bundle ID, хэш и реальное
состояние установки. Сетевая ошибка, неизвестная структура каталога, проблема
аккаунта или явный отказ Apple не превращаются в успешную загрузку.

AppRestore теперь явно передаёт `--platform iphone`; iPadOS также использует
пакеты `iPhoneOS`. Загрузка не содержит `--purchase`. Новая лицензия — отдельно,
после согласия пользователя, с проверками цены, лимитов и журналом. Не меняются
storefront, заголовки страны, DRM и подпись приложения. Истечение сертификата
само по себе в AppRestore не служит причиной запрета; окончательную установку
проверяет устройство. Получение файла и успешная установка — разные результаты.

## Возможности и использование

| Возможность форка | Использование в AppRestore |
|---|---|
| `auth login/info/revoke`, 2FA, редиректы | Вход, проверка аккаунта, выход; patch 0001 даёт страну аккаунта |
| Безопасный пароль связки (0003) | stdin/PTY; отдельный экран, не пароль Apple ID, не argv/env |
| `list-purchases --all` (0002) | Все покупки, поиск исчезнувших приложений; старый CLI имеет постраничный fallback |
| `search` | Поиск App Store; отсутствие результата не отменяет найденное в покупках |
| `download --app-id`, SINF, альтернативные серверные каналы | Основной путь возврата/экспорта; 0004 снимает зависимость fallback от карточки |
| `probe-download` (0005) | По явному диагностическому запуску: сравнение каналов на одном аккаунте без покупки, скачивания IPA и установки; отчёт содержит только разрешённые поля |
| `purchase` | Только отдельный шлюз, фиксированная нулевая цена запроса, лимиты и журнал; платные новые лицензии не запрашиваются |
| `list-versions` | Сейчас проверка живой сессии; отдельного выбора старой версии в GUI пока нет |
| `download --external-version-id`, `get-version-metadata` | Есть в форке, но пока не представлены пользователю в AppRestore; полезное следующее расширение — выбор доступной версии из своего аккаунта и сохранение version ID при экспорте |
| `mcp` | Не нужен для штатного восстановления; не запускается и не выставляет сессию наружу |
| macOS/tvOS/visionOS платформы | Не используются: AppRestore предназначен для iPhone/iPad |
| Completion, help, verbose | Help используется для capabilities; verbose только через скраббер, completion не нужен GUI |

## Поставка и проверка

GUI workflow собирает закреплённые исходники с патчами 0001–0005 и передаёт
свой архив упаковщику. GUI не скачивает старый опубликованный архив вместо
новой сборки. На этапе сборки выполняются Go-тесты `pkg/appstore` и `cmd`,
а self-test пакета проверяет все обязательные расширения до публикации.
Пользователь релиза не устанавливает Go и не собирает ipatool.

Старые CLI-установщики пока используют прежний закреплённый архив — эту
совместимость нельзя считать обновлённой поставкой всех патчей. Для нового
CLI-релиза нужны опубликованные архивы для каждой платформы и новые SHA-256.
Локально для проверки собран новый Windows-бинарник; macOS здесь не запускался.

Регрессии покрывают отсутствие карточки/offer, iPhone/iPad/default, неверный
ID/bundle, неоднозначный ответ, сохранение отказа Apple, остановку при сбое
каталога и проверку платформы до добавления SINF. Реальный ответ Apple на
снятое приложение остаётся необходимым финальным интеграционным тестом.

## Конкретная проверка: «Россельхоз»

В «Часто ищут» используется ID `1117817509`. Скрин пользователя показывал
сообщение «Apple не выдала лицензию … для страны … (RU)». Оно формировалось
GUI и само по себе не доказывает ни причину отказа, ни блокировку по стране:
одинаково перехватывались `9610` и `2059`, не различались операции.

Теперь выводится фактически достигнутый этап: исходная загрузка, запрос новой
лицензии или повторная загрузка/установка после её получения. Диагностика
содержит только фиксированную категорию ошибки и код магазина; сырой вывод,
пароли, email и токены в неё не попадают. Прежняя покупка пользователем пока
не подтверждена. Мок с этим ID проверяет `2059 → redownload` без карточки и
не является свидетельством фактической выдачи этого приложения Apple.

Повторный скрин пользователя подтвердил этап `license_request`, категорию
`temporarily_unavailable`, магазин `RU`: новая лицензия через текущий запрос
не получена. В закреплённом `appstore_purchase.go` уже есть `STDQ → GAME`
при `2059` для iOS; добавлять повтор тех же запросов не требуется. Этот ответ
не доказывает удаления IPA с серверов и не подтверждает отсутствие старой
лицензии во всех аккаунтах пользователя.

При проверке пути истории покупок найден отдельный локальный дефект:
после успешного открытия связки `_refresh_auth` вновь запускал безпарольный
`probe_keychain()`. Новый процесс не имеет пароля из памяти GUI, поэтому
сразу сообщает `locked`; Apple ID не определялся, история не привязывалась.
Теперь с открытой связкой читается `auth info` через штатный безопасный stdin
runner, затем запускается загрузка покупок для определённого аккаунта.
Это также покрывает преждевременный пустой scan из onboarding. Исправление
не считается доказательством успешного восстановления «Россельхоза».

Для банковских приложений похожее имя или иконка не подтверждают подлинность:
РСХБ [предупредил о поддельном «Россельхоз:Банк Онлайн» 16.03.2026](https://www.rshb.ru/news/16032026-000003).
Автоматически заменять исходный ID найденным одноимённым приложением нельзя.

## Сравнение со старой CLI и Infinity Blade III

Пользователь уточнил: игра загружалась ранней терминальной AppRestore на другом,
американском Apple ID. Это не контроль того же аккаунта/страны/момента времени.
Старый CLI мог автоматически применять `download --purchase`; нынешний GUI
отделяет новую лицензию от повторной загрузки. Cookies ipatool сохраняет после
каждого ответа, поэтому само разделение на два процесса не объясняет отказ.

Из уже сохранённой IPA прочитаны только технические поля: Infinity Blade III,
App Store ID `610003290`, bundle `com.chairentertainment.IB3`, версия `1.4.4`,
external version ID `838594835`. Сохранённая IPA не считается новым успешным
скачиванием. Текущее наличие этой игры или банков в лицензиях другого аккаунта
по этому файлу не устанавливается; Apple ID/SINF/токены из файла не извлекались.

Проверены изменения upstream от закреплённого `cde7d00` до `b0fe32d` (10.10.2026):
нового пути покупки для банков нет; изменения download касаются watchOS.
Сравнены исходники [ApplePackage, используемого Asspp](https://github.com/Lakr233/ApplePackage):
там те же `STDQ → GAME` для покупки и `volumeStore → redownload` для загрузки,
но минимальный payload без `serialNumber` и обработка pod-редиректов.
Это альтернативы для сравнения ответа, а не доказательство обхода отказа Apple.

## Одноразовая диагностика без покупки

`probe-download` опрашивает обычный и старый p25 volumeStore, redownload из bag,
канонический redownload с минимальным payload, затем (если известна версия)
закреплённые volumeStore/redownload/update/ent. Если версия неизвестна, её ищут
в каталоге страны этого аккаунта; отсутствие версии явно отражается в отчёте.
Номера чужих сборок не придумываются. Предложение URL и непустого SINF ещё не
доказывает успешную загрузку IPA или установку на устройстве.

Диагностика не вызывает `purchase`, не меняет storefront и не получает новую
лицензию. Каждый вызов ограничен временем; редиректы разрешены только на HTTPS
Apple Store/download dispatch, на тот же путь операции и GUID, максимум три.
URL, email, DSID, cookies, GUID, токен, SINF и сырые сообщения Apple в отчёт
не попадают. Проверяется ID приложения и (при закреплении) ID версии.

Запуск из исходников для конкретных примеров:

```powershell
.\.venv\Scripts\pythonw.exe -m apprestore_gui.app --ui quick `
  --diagnose-download 1117817509 --diagnose-download 1406492297 `
  --diagnose-download 610003290:838594835 `
  --diagnostics-output build/diagnostics/download-probe-RU.json
```

Следует сначала закрыть прежнюю GUI, чтобы не создавать второе окно. Затем
открыть связку штатным вводом пароля в GUI. Проверка автоматически начинается
после определения Apple ID, разблокировки связки и завершения загрузки истории.
Обычный запуск без флага ничего не проверяет. Смена аккаунта останавливает
диагностику; неуспешная проверка не запускает покупку автоматически.

Реальный read-only отчёт 12.10.2026, текущий RU Apple ID: оба банка возвращают
`9610` на обычном и старом p25 volumeStore, `3038` на обоих unpinned redownload;
версию каталог не выдал, поэтому закреплённые каналы не проверены для банков.
Игра на этом RU-аккаунте также возвращает `9610`, включая известную сборку
через ent/download; redownload отвечает `3038`. URL/SINF не предложены.
Неизвестный `3038` сохранён как отказ Apple, без выдуманной расшифровки.
Это не повторяет прежний успешный опыт на американском аккаунте.

Для контролируемого сравнения можно добавить `--diagnostics-country US` и
`--diagnostics-owned-control`: проверка ждёт подлинной страны вошедшего аккаунта
(не меняет её), затем добавляет один ID из его истории покупок. Другой аккаунт
выбирается самим пользователем. Выявлен и исправлен отдельный дефект кэша:
GUI-вход через PTY обходил `ipatool_login()` и мог оставлять прежнюю страну;
каждый успешный `auth info` теперь обновляет или сбрасывает кэш страны.
