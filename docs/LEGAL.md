### 1.3. Выводы для проекта (честно)

1. **Неофициальный клиент — серая зона.** П. F «only using Apple’s software» прямо про это. ipatool (и AppRestore поверх него) — не ПО Apple; плюс SAP/kbsync запускает куски CommerceKit/CoreFP в Unicorn. Устранить кодом нельзя — только описать и не усугублять. Практический риск: ограничение/блокировка Apple ID (п. G), не массовый иск. Публично известных массовых блокировок за ipatool не видела — это не гарантия.
2. **По смыслу условий допустимо:** redownload уже приобретённого на этом Apple ID (п. H) и явное, по желанию пользователя, получение бесплатного, которое Apple сама предлагает в его Home Country (п. B).
3. **Точно нельзя:** обход DRM/FairPlay, чужие аккаунты, платные без оплаты, подмена страны (A/M), массовые автоматические пробы каталога/лицензий (F), накрутка загрузок.
4. **Санкционный контекст (аккуратно, без гарантий).** Полка `popular_apps.py` — банки РФ, VK, MAX, убранные Apple из RU App Store; для части банков это связано с санкциями США (OFAC). П. O(g) EULA запрещает экспорт приложения лицам из SDN и в страны эмбарго. AppRestore не раздаёт IPA: файл отдаёт сервер Apple на Apple ID с лицензией. Но полка «вот приложения, которые Apple убрала» — **позиционирование продукта**. Риск для автора: жалоба Apple/GitHub, удаление репо/релизов. Риск для пользователя: блокировка Apple ID или отзыв redownload (п. H/J). Санкционную оценку я дать не могу — **уточнить у юриста, если полка остаётся**.

### 1.5. Патч ipatool `auth info` (storeFront / countryCode) — ✅ можно

Вывод в `auth info` полей **собственного** аккаунта (`storeFront`, `countryCode` / эквивалент) — **можно**: это чтение данных уже открытой сессии пользователя, без смены storefront и без чужих аккаунтов. Нужно шлюзу лицензий (lookup цены в стране аккаунта).

**Условие:** в логи GUI, self-test, bench и git **не** писать email / token / DSID из `auth info` — только код страны / id витрины (без PII). Подмена storefront по-прежнему ⛔ (см. [`research/region.md`](research/region.md)).

### 1.6. Замеры на аккаунте Евгения — решение владельца

Евгений разрешил на **своём** Apple ID бесплатные лицензии для замеров скорости/стабильности, **включая** снятые из App Store приложения (банки, Mail.ru и т.п. из полки), в пределах лимита **5/сутки и 15 всего**, через тот же шлюз (`price==0` где lookup отдаёт цену; запись в журнал).

Две жёсткие границы:
1. **Без смены storefront** при ошибках региона / «Account Not In This Store» — не патчить витрину, не подбирать чужой `X-Apple-Store-Front`.
2. **Стоп** при сигналах уровня аккаунта: блокировка («account is disabled»), запрос подтверждения личности/оплаты, повторная/зацикленная 2FA — прекратить прогон и сообщить Облачку / Евгению.

Это разрешение владельца аккаунта на замеры, не расширение политики для всех пользователей продукта. Вход и коды — только сам Евгений.

### 1.7. Механизм E — версия из MDM-каталога `cc=ru` при US-аккаунте — ⚠️ можно при условиях

**Суть:** для приложения, которое **уже есть** в `list-purchases` аккаунта, взять публичный `external-version-id` из MDM/consumer lookup с `cc=ru` и скачать **эту** версию, отправив запрос со **своим** (US) `storeFront` из сессии. Это **не** смена региона и **не** подмена `X-Apple-Store-Front`: из чужого каталога берётся только публичный идентификатор версии.

**Вердикт:** ⚠️ можно при условиях.  
**Не запускаем** до отдельного «да» Евгения (регион он пока держит на бумаге).

**Условия:**
1. Только приложения из `list-purchases` **этого** Apple ID.
2. Без `ipatool purchase` / без `--purchase`.
3. Без подмены `storeFront` / заголовков страны.
4. При отказе Apple — следующее приложение; **не** перебирать другие витрины (`cc=`).
5. В журнал / отчёт замеров — пометка источника версии `cc=ru` (без email/токенов).

Связь с [`research/region.md`](research/region.md): не путать с подменой витрины; публичный MDM lookup сам по себе ✅ (§3 таблица, механизм 3).

### 1.8. Единичный эксперимент (прямое «да» Евгения, 10.10.2026 ~17:57 МСК)

В чате команды Евгений дал **одноразовое** согласие: одна попытка взять **бесплатную** лицензию и скачать приложение, которого **не было** в US-магазине, **удалено** из App Store и **нет** на аккаунте; со своим US `storeFront`; через `acquire_and_record` (шлюз + журнал), в пределах лимита 5/15.

Это **не** исключение из механизма E (§1.7) и **не** разрешение на подмену региона.

**Граница перед запуском:**
- Цену в `license_guard` / шлюз **вручную не подставляем**.
- `purchase` только если по коду ipatool `cde7d00` в `buyProduct` явно уходит `price=0` / `pricingParameters` для бесплатного и при несовпадении (нет offer / не тот магазин) Apple **отказывает**, а не списывает оплату. Иначе — **стоп**, зафиксировать результат, не повторять.
- Лимит и журнал как обычно; без смены storefront; стоп при сигналах уровня аккаунта (§1.6).

**Результат попытки (отчёт Макса, 10.10.2026 ~18:15 МСК):**
- Одна попытка `ipatool purchase --app-id 492224193` (СберБанк Онлайн), US storeFront `143441-1,34` без подмены, цена в запросе фиксированная `0`.
- Ответ Apple: HTTP 200, `failureType 2040`, `customerMessage "Purchase of this item is not currently available"`, `jingleDocType` пусто, `status 0`.
- Лицензия не выдана, списания нет, скачивания нет, повторов не было.

**Вывод:** с US-аккаунта без подмены витрины Apple не отдаёт удалённое приложение, которого в US не было (код 2040).  
**Для продукта:** `2040` = явный отказ (`refused`), в лимит **не** считается; не повторять; другие витрины не пробовать.

**Инциденты и требования:**
1. Отказ по ошибке записан как `purchase_uncertain` из-за регистра поля `FailureType` (чинится). Требование: журнал **append-only** — ошибочные строки не удалять, а дописывать корректирующую строку `status: "voided"` со ссылкой на исходную (`time` + `track_id`); счётчик лимита учитывает `voided` и не считает аннулированную строку.
2. Cookie сессии (`wosid-lite`) на мгновение попали в терминальный вывод `--verbose`; в файлы не попали. Требование: потоковый скраббер **до** вывода; в продукте `--verbose` только через скраббер.


### 1.9. Попытка B: подмена витрины, одна попытка (прямое «да» Евгения в чате, 10.10.2026 ~18:48 МСК)

Разовое согласие Евгения, данное им самим в чате команды. Это **не** разрешение для продукта: R5 и ⛔ в §3 (п. 12, 20) остаются в силе.

**Условия:** один `buyProduct`; меняется только `X-Apple-Store-Front` (`143469-1,34`: id RU и хвост аккаунта); оба автоповтора ipatool выключены (Arcade-ретрай и `retry.Do` с перелогином); без скачивания; любой ответ окончательный; код подмены только в песочнице, ни в какие ветки.

**Результат (отчёт Макса, 10.10.2026 18:49 МСК; дословный ответ хранится локально у команды, вне репозитория, секреты вычищены):**
- Ровно один `buyProduct` на `p29-buy.itunes.apple.com`, сервер эхом подтвердил `X-Apple-Request-Store-Front: 143469-1,34`.
- Ответ Apple: HTTP 200, `failureType -128`, `customerMessage "Account Not In This Store"`, `jingleDocType` пусто, `status 0`. ipatool rc=1.
- Лицензия не выдана, журнал без записи (`recorded=false`, used 0/0), скачивания и повторов не было. Запросов 2FA, оплаты, подтверждения личности или смены страны не было, сигналов блокировки нет.

**Вывод:** сервер покупок сверяет витрину с аккаунтом и отказывает (`-128`) ещё до проверки приложения. Подмена витрины на чужом по стране аккаунте технически бесполезна и юридически запрещена. Вердикт ⛔ подтверждён фактом; повторять и пробовать другие витрины нельзя.

**Для продукта:**
- `-128` / «Account Not In This Store» обрабатывать как явный отказ (`refused`), без записи в журнал и без повтора.
- Продукт сам витрину не меняет, поэтому `-128` в продукте означает рассинхрон: витрина из сессии не совпала со страной аккаунта (смена страны Apple ID, старая сессия). Пользователю: «Приложение недоступно в магазине страны вашего Apple ID»; подсказка: выйти и войти заново. VPN и смену региона не советовать (R5).

**Журнал лицензий, правило поправок (согласовано с Максом и Димой):**
- `voids: <id>` только гасит ошибочную запись; погашенная в лимит не идёт.
- `amends: <id>` меняет статус цепочки; в лимит идёт последний статус. `acquired`, `acquired_download_failed`, `purchase_uncertain` считаются, `voided` нет. Цепочка `acquired` → `amends: acquired_download_failed` = 1 место.
- Старые записи без `id` гасятся только явным `voids`; псевдонима `amends` = `voids` нет.


### 1.10. Классификация «нет в регионе» / «удалено» через публичный lookup чужой витрины — ⚠️ можно при условиях (10.10.2026)

Тот же класс, что публичный MDM/consumer lookup (§1.7, §3 механизм 3): чтение публичных метаданных, без входа и покупки.

**Условия:**
1. Только анонимный запрос к публичному lookup: без сессии, cookie, токена, DSID и `X-Apple-Store-Front` аккаунта, без данных, связывающих запрос с Apple ID.
2. Только приложения из списка самого пользователя (с телефона или из `list-purchases`); обход каталога запрещён.
3. Одна-две фиксированные эталонные витрины; перебор стран запрещён; кэш и ограничение частоты.
4. Результат — только подпись к приложению. У группы «Нет в регионе» нет действий: никаких «купить там», «сменить регион», VPN. Покупка только через шлюз и только в витрине аккаунта.

**Смежные решения UI (10.10.2026):**
- Сетевая ошибка входа: «Проверьте подключение к интернету и попробуйте ещё раз»; совет про VPN убрать (R5).
- Без интернета на компьютере разрешено возвращать только сгруженные приложения (уже числятся на iPhone, новая лицензия не нужна). Всё, что идёт через шлюз, без сети неактивно.
- «Вернуть все N»: экран согласия с выбором «Продолжить» / «Только уже купленные» / «Отмена», сам не закрывается; в K только бесплатные с подтверждённой ценой 0 и без лицензии на аккаунте; числа из `read_counts`; при исчерпании лимита список «не хватило лимита», без автоочереди.
- `-128` / `STORE_MISMATCH`: отдельный код, не сессия; «На главный» основная, «Войти заново» вторичная, без автоповтора; при повторе финальный текст без входа; признак «уже входили» только в памяти.


### 1.11. Сторонний каталог `ipafilezone.com` в поиске (`catalog.search_ipafilezone_apps`) — ⚠️ не рекомендую, решение Евгения (10.10.2026)

**Что делает код** (`apprestore_core/catalog.py:714`): GET `https://ipafilezone.com/api/search?q=<запрос>&per_page=N`, из ответа берёт только `trackId`, название, разработчика. Файлы IPA не скачивает, ссылок на файлы не отдаёт. Дальше установка идёт обычным путём: Apple, шлюз лицензий, аккаунт пользователя. DRM не обходится.

**Риски:**
1. Репутация: продукт в интерфейсе (CLI «iTunes + IPA Filezone», «ни в iTunes, ни в архиве»), в `CHANGELOG.md` и в коде связывается с каталогом IPA-файлов. Это противоречит позиции «только свои покупки через Apple» и может читаться как отсылка к стороннему распространению.
2. Приватность: поисковые запросы пользователя уходят третьей стороне без уведомления. Apple ID туда не уходит.
3. Надёжность: внешний сервис может исчезнуть или менять ответ, а мы зависим от него в поиске.

**Вывод:** юридического блокера в чтении метаданных нет, но в продукте это не нужно: для поиска хватает iTunes Search/lookup и покупок аккаунта.
- 4b: не подключаем (решено), «…и архиве» убрать из `PickerSheet.qml`, тест на отсутствие обращений.
- CLI и старое окно: рекомендую убрать источник. Если Евгений оставит — выключено по умолчанию, отдельный флаг, название сайта не в пользовательских текстах, строка в README о том, что запрос уходит третьей стороне.


### 1.12. Поиск удалённых по названию: встроенный список + Wayback Machine (Internet Archive) — ⚠️ можно при условиях (10.10.2026)

Источник: публичные архивные снимки страниц `apps.apple.com`. Берём только метаданные (название, разработчик, track_id, bundle id, иконка). Дальше обычный путь: Apple ID, экран согласия, шлюз лицензий. IPA-каталоги запрещены (§1.11).

**Условия:**
1. **Приватность.** В архив уходит только текст запроса (и IP пользователя, как при любом HTTP). Без Apple ID, почты, UDID, списка приложений, cookie. Архив вызывается только запасным путём: когда App Store, покупки и встроенный список ничего не дали.
2. **Уведомление.** Тихая сноска под результатами из архива: «Поиск удалённых приложений идёт через публичный архив Internet Archive (web.archive.org). Туда отправляется только текст запроса, ваш Apple ID — нет.» В настройках переключатель «Искать в архиве» (по умолчанию вкл.); при выкл. остаются App Store, покупки и встроенный список. Строка о том же в README/FAQ.
3. **Вежливый доступ.** Не чаще 1 запроса/сек, кэш, честный `User-Agent` с названием программы, без обхода ограничений архива; при 429/5xx — стоп и текст «Архив сейчас не отвечает».
4. **Статус «удалено» — по факту.** Снимок архива исторический. Пометку «Удалено из App Store» ставим только после проверки текущего наличия через `region_probe` (§1.10); если приложение сейчас есть в витрине аккаунта — это обычный результат App Store.
5. **Иконки.** Только для опознания, в уменьшенном виде, локальный кэш; не распространяем и не кладём в репозиторий.
6. **Встроенный список и «замаскированные» названия (например, «Сириус» → ВТБ) — главный риск: фишинговые клоны банков.** В список попадает связь только с подтверждением из официального источника банка (сайт, официальный канал, пресс-релиз) с указанием ссылки и даты проверки в самом списке. Сопоставляем по track_id **и** разработчику; при расхождении разработчика — не показываем. Без подтверждения — в список не идёт. В результате всегда виден разработчик.
7. Никаких формулировок «обход блокировки» / «санкций» / «скрытое приложение банка» в UI и текстах.


### 1.13. Встроенный список удалённых приложений: уровни подтверждения (решение Лены, 10.10.2026)

Уточняет §1.12 п.6 после проверки Макса: из 9 записей у 7 разработчиком на странице App Store указано физлицо, а не банк.

**Уровень A — ✅ можно (4 записи: ВТБ Онлайн 472951966, Альфа-Банк 353127685, Делим Вместе 6739035108, Drive Transit 6760469916).** Прямая ссылка из официального канала банка на конкретный track_id сильнее совпадения имени разработчика. Условия:
1. В списке у записи: ссылка на официальный источник банка (пост в официальном канале, страница официального сайта, пресс-релиз) с прямой ссылкой на track_id, **архивная копия этого источника** (его могут удалить), дата проверки. Без архивной копии запись не идёт.
2. В строке выдачи разработчик со страницы как есть. Если разработчик не банк, второй строкой: «Ссылку на это приложение публиковал банк». Не писать «это ВТБ», «замаскированное», «обход блокировки».
3. Только в ответ на запрос пользователя. Никаких витрин и подборок «банки, которые удалили», никаких подсказок в пустом поиске.
   Исключение по решению Евгения: блок «Часто ищут» до ввода — см. §1.15.
4. Установка — обычный путь: шлюз, цена 0, лимит. Если Apple отказывает (2040 и т. п.), честный отказ без повторов.
5. Перепроверка при каждом изменении списка; если банк удалил или опроверг ссылку — запись убираем.

**Уровень B — ⛔ выключен (`BUILTIN_STRICT=True`).** Совпадение названия и даты по снимку Wayback для банковских приложений недостаточно: высокий риск фишингового клона. Возврат к B — только с ссылкой уровня A.

**Оригиналы с разработчиком-банком (Сбер 492224193, Т-Банк 455652438 и т. п.) — ✅** при официальной ссылке банка и совпадении разработчика.


### 1.14. Удалённое приложение с неизвестной ценой: попытка через Apple — ⚠️ можно при условиях (10.10.2026)

Основание: в ipatool `cde7d00` `buyProduct` всегда отправляет `price=0` (`appstore_purchase.go:134`); платное по такому запросу Apple не выдаёт, а отказывает (попытки A/B: явные отказы 2040 / -128, списаний нет). Для удалённых авторитетом по цене становится сервер Apple. Это узкое исключение из «цена неизвестна = отказ», не общий обход.

**Условия:**
1. Флаг ставит только `region_probe` (`DELISTED` / `NOT_IN_REGION`). Не GUI, не встроенный список, не пользователь.
2. Если хоть один lookup (витрина аккаунта или эталонная) показал цену > 0 — это платное: кнопки нет, попытки нет.
3. Только патченый ipatool, прошедший preflight (`can_acquire_license`), сборка с фиксированным `price=0`. Иначе — `NEEDS_PATCHED_BUILD`, без попытки. Цену в запрос ни из каких других источников не подставляем.
4. Обычный путь: экран согласия (такие приложения входят в K, без слова «бесплатно»), шлюз, лимит 5/15 проверяется до попытки.
5. Журнал: выдано → `acquired` (+ `price_source: "apple_fixed_0"`); явный отказ (непустой FailureType) → без записи и без повтора; неясный ответ → `purchase_uncertain`, считается в лимит.
6. Одна попытка на приложение за сессию.
7. Первый живой прогон — с проверкой истории покупок Apple ID после (смоук п.19). Любое списание — стоп функции до разбора.


### 1.15. «Часто ищут» — осознанное решение Евгения (10.10.2026)

**Решение.** Евгений (владелец проекта) решил вернуть в «Найти» до ввода полный список из `apprestore_gui/popular_apps.py` (коммит `b3f869a`): все 33 записи, с прежними id и подписями без приписок. Например, плитка «ВТБ» ставит 6749962031 («Сириус»), «Т-Банк» — 6755181069, «Альфа» — 6473656113.

Это отступление от §1.13 (уровень A, п.3 «никаких подсказок в пустом поиске») и от прежнего правила «связи с банком нигде не утверждаем». Решение принято владельцем сознательно. Лена его фиксирует, а не одобряет как юридически безрисковое.

**Риски, которые Евгений принимает:**
1. Подпись с названием банка над приложением другого разработчика может читаться как утверждение, что это официальное приложение банка: введение в заблуждение, претензии правообладателя товарного знака, жалобы Apple или банка.
2. Если под id окажется мошенническое приложение, проект сам направит к нему людей, которые вводят туда банковские данные.

**Условия, которые остаются обязательными:**
1. Нажатие на плитку идёт через тот же шлюз, что и любое «Поставить»: `acquire_and_record()` с preflight, лимитами, журналом. Обхода шлюза нет, это покрыто тестом.
2. Каждый из 33 id сверяется по таблице Макса (название, разработчик, последняя версия по архиву). Id, который не соответствует приложению, которое Евгений имел в виду, или не находится, убирается или исправляется. Решение касается его 33 приложений, а не любого содержимого под этими id.
3. Иконки только с CDN Apple (`mzstatic.com`, ссылка из архивной копии lookup Apple), загрузка анонимно, без cookie, с кэшем. Иконки с сайтов банков (`ICON_SITES`), буквы и цвета брендов не используются.
4. README и посты не утверждают, что приложения официальные.

**Пересмотр:** при первой жалобе банка, правообладателя или Apple либо если какой-то id окажется мошенническим приложением.

### 2.3. `apprestore_gui/account_vault.py` — ⚠️ можно при условиях

**Что делает:** копирует файлы live-сессии ipatool (`account`, `cookies`, `kbsync-v1`) в `~/.apprestore/keychains/<email>/`. Пароль Apple ID в vault **не пишется отдельно**. Но в исходнике ipatool `pkg/appstore/account.go` структура `Account` содержит поле `Password` — оно лежит **внутри** зашифрованного blob `account` (FileBackend keyring + passphrase). Копия = копия уже зашифрованного blob, не plaintext.

**Вердикт:** ⚠️ можно при условиях.  
**Риск:** несколько сессий = больше поверхность кражи с диска; перепутать активный аккаунт; в `main_window._revoke` **нет** вызова `forget_session` (в `quick_session.signOut` — есть) → при выходе из старого GUI копия в vault остаётся; нет `chmod 0o600` / `0o700` на файлы vault (в отличие от `service.py` library).  
**Правка:**
1. `account_vault.py`: после `_copy_session` выставить `chmod 0o700` на каталог и `0o600` на файлы; `vault_root().mkdir(mode=0o700)`.
2. `main_window._revoke`: после `revoke()` вызывать `forget_session(email)` для активного email (как в `quick_session.signOut`).
3. Не хранить passphrase в файле; в памяти на сессию — ок (уже так).
4. UI: при переключении аккаунта явно показывать «сейчас: email@…».
5. Документировать в SECURITY.md: что в blob, права на файлы, что делает «Выйти».

### 2.4. `auth_pty.py` / вход — ⚠️ можно при условиях

**Факт:** пароль/2FA/passphrase идут в stdin pty, не в argv/env (`tools.py::_ipatool_cmd` это комментирует). `_visible_output` маскирует секреты в transcript. На POSIX `_login_posix` передаёт `on_output(text)` **до** маскировки — если GUI пишет сырой вывод в лог, секрет может утечь. Windows/ConPTY-путь маскирует до `on_output`.

**Правка:** в `_login_posix` пропускать через `_visible_output` перед `on_output`; не писать email в verbose-логи; после успеха не оставлять password/code в полях ввода (проверить QML/Widgets).

### 3.1. Особый фокус (по запросу)

- **Смена storefront/региона:** подмена заголовка в клиенте — ⛔ / технически обычно бесполезна (см. [`research/region.md`](research/region.md)). Легитимно: официальная смена страны Apple ID или второй свой аккаунт. UI: «страну магазина программа не меняет».
- **iPad-вариант (`--platform ipad`):** ✅ можно — это выбор семейства пакета под устройство пользователя, не смена региона. Связать с моделью из lockdown.
- **list-purchases:** ✅ основа «Мои покупки» и честной полки.
- **list-versions + externalVersionId:** ✅ главный запрос сообщества; только при лицензии.
- **MDM lookup:** ✅ для живых карточек; для полки delisted бесполезен.
- **Механизм E** (MDM `cc=ru` → version id при US-аккаунте): ⚠️ §1.7; не запускать до «да» Евгения.
- **Единичный эксперимент license+download вне US-каталога:** §1.8 (результат — по отчёту Макса).
- **Range-докачка:** ✅ только надёжность, права не затрагивает.

## 5. Блокеры и открытые решения

1. **Релизный блокер — патч `auth info`:** без `storeFront`/`countryCode` в релизных бинарниках страна аккаунта неизвестна → шлюз отказывает в новой лицензии (коммит Димы `e725738`). Тег/релиз — только после «да» Евгения на включение патча в релизную сборку.  
2. **Кэш покупок** `~/.apprestore/purchases/purchases-cache.json` — личные данные: права `0600` на файл / `0700` на каталог; удалять при выходе и при смене аккаунта; без email/токенов/UDID в содержимом.  
3. **Шлюз лицензий** — единый `license_gate` + `PurchaseGrant`; обход недопустим.  
4. **Подмена storefront / механизм E** — E только после «да» (§1.7); подмена заголовка в код не включать.  
5. **Живые прогоны / замеры** — §1.6; единичный эксперимент §1.8 — по отчёту Макса.  
6. **RU-редакция AMS Terms** — сверить перед релизом с дисклеймером.  
7. Остаточный риск полки банков (§1.3 п.4) — без гарантий; с полки purchase через тот же шлюз (не «никогда»).
