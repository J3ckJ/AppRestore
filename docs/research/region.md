# Storefront / регион App Store: что реально умеет ipatool и AppRestore

**Автор:** Лена · **Дата:** 10.10.2026, МСК  
**Запрос:** Евгений — рассмотреть механизм «подмены региона» целиком: реально ли, что даст, риски, рекомендация.  
**Границы:** только чтение исходников и публичные HTTP-запросы. **Входов в Apple ID и `--purchase` не было.** Где поведение сервера при живой сессии не подтверждено — помечено **гипотеза**.

Связанные документы: [`docs/LEGAL.md`](../LEGAL.md), исследование Макса M-2 (`maks-research/app-store-mechanisms.md` §12), `docs/IPATOOL.md` (PR #11).

## 1. Откуда ipatool берёт storefront

База: `majd/ipatool` коммит `cde7d00` (наша сборка «2.6.0+redirect»), дерево `/workspace/apprestore/maks-scratch/ipatool`.

| Шаг | Код | Факт |
|---|---|---|
| Вход | `appstore_login.go` ~197–213 | После успешного `authenticateAccount` читается заголовок ответа `X-Apple-Store-Front` (`HTTPHeaderStoreFront`) и кладётся в `Account.StoreFront`. Также сохраняются `PasswordToken`, `DirectoryServicesID` (DSID), `Pod`. |
| Подсказка при логине по телефону | `appstore_login_storefront.go` | Для номеров CN/IN выставляется **стартовый** `X-Apple-Store-Front` в *запросе* логина. Комментарий в коде: *«does not change the Apple ID sent to Apple»* — это routing hint, не смена страны аккаунта (PR [#612](https://github.com/majd/ipatool/pull/612)). |
| Lookup / search | `appstore_lookup.go`, `storefront.go` | `countryCodeFromStoreFront(acc.StoreFront)` → параметр `country=` в iTunes Lookup/Search. Карта `storeFronts` (RU = `143469`, US = `143441`, …). |
| Purchase | `appstore_purchase.go` ~61–62, 107–121 | В запрос уходит **`acc.StoreFront`** как `X-Apple-Store-Front`, плюс `X-Token` / `X-Dsid` того же аккаунта. |
| Download (kbsync / volume / redownload) | `appstore_kbsync.go` ~122 и download-цепочка | Тот же `acc.StoreFront` в заголовках. |
| CLI | `cmd/*.go` на `cde7d00` | **Нет** флага `--country` / `--storefront` для подмены. (В истории issues есть сторонний PR/ветка с `--country`, [#476](https://github.com/majd/ipatool/issues/476) — **не** в нашей линии.) |

**Итог по коду:** storefront в рабочей сессии = то, что Apple вернула при логине для этого Apple ID. Клиент его **повторяет**, а не выбирает произвольно. Подменить заголовок в одном запросе, оставив токен/DSID от другого Home Country — в нашей сборке штатно нельзя; даже если пропатчить вручную, токен остаётся от аккаунта.

## 2. Что происходит при «чужом» storefront (по источникам)

| Ситуация | Источник | Что известно | Статус |
|---|---|---|---|
| Lookup/search с `country=` другой страны | Публичный API; код lookup | Меняется **каталог**: какие карточки видны и цена. Не требует входа. Не меняет лицензии. | **Проверено** публично (см. §5) |
| Purchase после **официальной** смены региона аккаунта US→IN | ipatool [#456](https://github.com/majd/ipatool/issues/456) | `FailureType 5002`, `CustomerMessage: An unknown error has occurred` на `buyProduct` STDQ, хотя приложение «доступно в Индии». | По issue (закрыт); воспроизведение на нашем аккаунте — **гипотеза / проверка при входе Евгения** |
| Download delisted, которого нет в текущем каталоге storefront | [#620](https://github.com/majd/ipatool/issues/620) (AliExpress, IN), [#577](https://github.com/majd/ipatool/issues/577) | Часто падает на этапе version lookup (`platform version lookup returned no app` / пустой enterprise+consumer catalog), даже если раньше redownload работал. | По issue; для наших банков — см. §5 (каталог пуст везде) |
| Подмена только заголовка `X-Apple-Store-Front` при живом токене другого региона | Логика AMS + привязка token/DSID; мнение в M-2 §12 | Ожидаемый отказ или игнор: сервер сверяет сессию с Home Country аккаунта. | **Гипотеза** — без входа не проверяли и **не будем** подменять на чужом/тестовом без явного «да» |
| Пустой storefront в аккаунте | [#303](https://github.com/majd/ipatool/issues/303), [#487](https://github.com/majd/ipatool/issues/487) | `country code mapping for store front () was not found` — ломается lookup, не «открывает другой регион». | По issue |

Тексты AppRestore уже честные: `errors.py` — «Apple не отдаёт это приложение для страны этого Apple ID. Программа страну магазина не меняет.»

## 3. Привязана ли лицензия к стране?

| Вопрос | Что можно сказать сейчас |
|---|---|
| Home Country аккаунта | AMS Terms §A: сервисы для страны/территории проживания; создание аккаунта задаёт Home Country. Family Sharing (§M): все члены семьи — один Home Country. |
| Redownload после снятия из каталога | AMS Terms §H: redownload на устройства с тем же Apple Account; контент могут перестать отдавать. **Гипотеза для проверки:** если лицензия уже была на аккаунте до снятия/до смены страны, download-цепочка иногда ещё отдаёт пакет; после смены страны часть owned может перестать находиться (отзывы Threads: @rare_bear — после смены региона с РФ одно приложение не выгружается; @e440 — мультирегиональные сценарии). |
| Новая лицензия (`purchase`) в «чужом» каталоге | Без смены Home Country — не наш путь. После официальной смены страны — [#456] показывает, что даже «доступное в новой стране» иногда даёт 5002. |
| Delisted банки РФ / VK / MAX | Публичный каталог пуст во всех проверенных `cc` (§5) → **подмена региона клиента карточку не вернёт**. Путь только лицензия+download на аккаунте, где приложение уже было. |

## 4. Легитимные варианты у пользователя (не подмена заголовка)

1. **Официальная смена страны Apple ID**  
   Инструкция Apple: https://support.apple.com/en-us/118283 (обновлялась 05.10.2026).  
   Условия до смены: потратить баланс, отменить блокирующие подписки и дождаться конца периода, дождаться pending (pre-order, rental, refunds), при Family Sharing — возможно нужно выйти из семьи, способ оплаты и адрес новой страны. Apple прямо советует **перед сменой** скачать/перекачать контент, который в новой стране может быть недоступен.  
   Если не хотите указывать оплату новой страны — Apple предлагает создать **новый** Apple Account, уже находясь в этой стране.

2. **Второй (свой) Apple ID другой страны**  
   Отдельный аккаунт с собственным Home Country. В AppRestore это как раз сценарий vault / несколько сессий — без подмены заголовков. Нужны условия из LEGAL §2.3 (права на файлы, не путать активный аккаунт).

3. **«Мультирегиональные» практики из отзывов**  
   Пользователи описывают приложения из разных сторов на одном устройстве / сложные истории со сменой региона. Это **не** то, что программа должна эмулировать заголовком. Мы можем: показать страну текущего аккаунта; честно сказать, что недоступно; предложить войти другим своим Apple ID (если пользователь сам им владеет).

## 5. Публичные пробы 10.10.2026 (без входа)

Запросы: `itunes.apple.com/lookup?id=492224193,6749962031,564177498,686449807&country=<cc>` для `cc ∈ {ru,us,kz,by,am,de,tr}` и MDM `uclient-api` lookup для Сбер/Telegram.

| ID | Приложение | Результат |
|---|---|---|
| 492224193 | Сбер | **пусто** во всех 7 `cc`; MDM iphone ru/us — без offers |
| 6749962031 | ВТБ Сириус | **пусто** во всех 7 `cc` |
| 564177498 | VK | **пусто** во всех 7 `cc` |
| 686449807 | Telegram | найден во всех 7; MDM ru/kz — offers=1 |

**Вывод пробы:** для полки delisted «переключить регион lookup» ничего не даёт — карточек нет ни в RU, ни в US/KZ/…. Для живых приложений другой `country=` меняет только витрину, не лицензию.

## 6. Технический вердикт

| Вопрос | Ответ |
|---|---|
| Реально ли «подменить регион» в нашей сборке ipatool? | **Штатно — нет** (нет флага; storefront с логина). |
| Реально ли пропатчить заголовок вручную? | **Частично как эксперимент**, но **обычно бесполезно**: purchase/download несут token+DSID аккаунта; каталог delisted пуст везде. Полезный эффект не подтверждён. |
| Что реально даёт смена `country=` в публичном lookup? | Другая витрина для **живых** приложений (цены, наличие). Для нашей полки банков/VK — ничего. |
| Что даст пользователю официальная смена страны / второй Apple ID? | Другой Home Country и другой каталог/политика purchase; ценой потери части redownload и возни с оплатой/подписками (статья Apple). |

## 7. Правовые риски и рекомендация

**Риски подмены storefront в клиенте:**
- AMS Terms §A (Home Country), §M (Family Sharing — один Home Country), §F (нельзя обходить/скриптовать сервисы нештатно).
- Риск ограничения Apple ID (§G), особенно вместе с частыми неудачными purchase (см. 5002 в #456).
- Ложные обещания в продукте («выберем регион — банк вернётся») при пустом каталоге.

**Рекомендация Лена:**
1. **Не внедрять** подмену `X-Apple-Store-Front` / `--country` для обхода.  
2. В UI оставить и усилить: показ страны текущего Apple ID; «программу страну не меняет»; при ошибке региона — короткая ссылка на официальную смену страны (support.apple.com/118283) и на вход **другим своим** Apple ID.  
3. Для delisted полки опираться на `list-purchases` + download без purchase-пробы, не на «другой регион».  
4. Vault нескольких своих Apple ID — легитимный продуктный путь (с security-условиями).

## 8. Что проверить при входе Евгения (безопасно, по одному приложению)

Без подмены заголовков:

1. `auth info --format json` → записать **только** storefront id / country code / pod (без email/token).  
2. Owned + delisted (если есть на аккаунте): `download` **без** `--purchase` → success / 9610 / No Longer Available / version lookup empty.  
3. После **официальной** смены страны (если когда-либо будет) — не наш сегодняшний прогон; иметь в виду #456 на purchase.  
4. Не делать: патч StoreFront в blob аккаунта, массовый purchase, чужие аккаунты.
